## Overview

Phase 2 constructs the complete meteorological data ingestion, validation, and harmonization layer for the RAMP pipeline. This layer sits between raw NWP data sources and the Phase 3 ML regime classifier.

```
Raw NWP Files (GFS/GEFS/NCMRWF)
      │
      ▼
  Provider Adapter
  (WeatherForecastProvider ABC)
      │
      ▼
  Grid Harmonization       Unit Normalization       Time Alignment
  (harmonisation/grid.py)  (harmonisation/units.py) (harmonisation/time.py)
      │                           │                       │
      └───────────────────────────┼───────────────────────┘
                                  │
                                  ▼
                         NWPForecastBundle
                         (canonical internal form)
                                  │
                                  ▼
                     Quality Engine (validation/quality.py)
                     ValidationReport (JSON + Markdown)
                                  │
                                  ▼
                        Data Manifest Registry
                        (validation/manifest.py)
                                  │
                                  ▼
                         Phase 3 ML Feature Engineering
```

## Scientific Invariants (ENFORCED IN CODE)

### Invariant 1: Time Alignment
```
forecast_valid_time = initialization_time + timedelta(hours=lead_time_hours)
```
Observations **must** be matched by `forecast_valid_time`, never by `initialization_time`.

This invariant is enforced in:
- `ForecastTimeSpec.__post_init__()` — raises `ValueError` on timezone-naive init times
- `align_forecast_to_observation()` — contains explicit safeguard logging if init_time would match instead of valid_time
- Tests: `test_aligns_to_valid_time_not_init_time()` — regression test that would catch this bug

### Invariant 2: Extreme Rainfall Preservation
```
if rainfall > 300 mm/24h → flag VALID_EXTREME, NOT INVALID, NOT DELETED
```
300 mm/24h is physically possible in the Indian monsoon (documented events in Kerala, Mumbai).

Enforced in:
- `VARIABLE_BOUNDS["rainfall_mm"].extreme_max = 300.0`
- `flag_array()` — maps extreme values to `QualityFlag.VALID_EXTREME`
- Tests: `test_extreme_rainfall_is_valid_extreme_not_invalid()`

### Invariant 3: No Data Fabrication
All providers that lack local data files **must** raise `ProviderUnavailableError`, never generate synthetic substitutes and claim them as real.

Enforced in:
- `NCMRWFProvider.get_forecast()` — explicitly raises `ProviderUnavailableError`
- `GFSProvider.get_forecast()` — same
- Tests: `test_raises_provider_unavailable_never_fabricates()`

### Invariant 4: SYNTHETIC_DEMO Tagging
Any data generated by `SyntheticNWPProvider` or `SyntheticObservationProvider` is **always** tagged `DataMode.SYNTHETIC_DEMO`. This tag propagates through all downstream bundles.

### Invariant 5: Units Read From File
Source units for each variable are read from file metadata attributes, not hardcoded assumptions. Only the **target** units are hardcoded in `CANONICAL_TARGET_UNITS`.

## Directory Structure

```
data/
├── raw/
│   ├── nwp/
│   │   ├── gfs/          # GFS 0.25° GRIB2 files
│   │   │                 # Format: gfs_YYYYMMDD_HHz_f{lead:03d}.grib2
│   │   ├── gefs/         # GEFS 0.5° GRIB2 files (per-member)
│   │   │                 # Format: gefs_YYYYMMDD_HHz_pXX_f{lead:03d}.grib2
│   │   └── ncmrwf/
│   │       ├── ncum/     # NCMRWF NCUM NetCDF (institutional access required)
│   │       └── neps/     # NCMRWF NEPS NetCDF (institutional access required)
│   ├── observations/
│   │   └── imd/          # IMD 0.25° gridded daily rainfall NetCDF
│   │                     # Format: imd_rainfall_YYYY.nc (annual) or daily
│   └── auxiliary/
│       ├── dem/          # Digital Elevation Model (SRTM/ALOS)
│       └── shapefiles/   # India state/district boundaries
├── interim/
│   ├── normalized/       # Unit-normalized datasets (post-conversion)
│   ├── regridded/        # Spatially regridded to 0.25° RAMP target grid
│   └── aligned/          # Time-aligned forecast-observation pairs
├── processed/
│   ├── features/         # Engineered feature tensors (Phase 3 input)
│   └── training/         # Training/validation/test splits
├── metadata/
│   ├── datasets/         # data_manifest.json
│   ├── schemas/          # Variable schema JSON
│   └── validation/       # Validation reports (JSON + Markdown)
└── cache/                # Temporary computation cache
```

```
Domain:     India (6.5°N – 38.5°N, 66.5°E – 100.5°E)
Resolution: 0.25° × 0.25°
Grid Size:  129 lat × 137 lon = 17,673 grid points
```

All NWP data is regridded to this grid before feature engineering.

## Unit Normalization Map

| Variable | Source Unit (typical) | Normalized Unit | Conversion |
|---|---|---|---|
| `precip_nwp_raw` | `kg/m²` (GFS) | `mm` | 1 kg/m² = 1 mm |
| `precip_nwp_raw` | `m` (ERA5) | `mm` | × 1000 |
| `t850`, `t500` | `K` | `°C` | − 273.15 |
| `mslp` | `Pa` | `hPa` | ÷ 100 |
| `u850`, `v850` | `m/s` | `m/s` | identity |
| `cape`, `cin` | `J/kg` | `J/kg` | identity |
| `pw` | `kg/m²` | `kg/m²` | identity |

## Regridding Choices

| Variable Type | Method | Reason |
|---|---|---|
| Precipitation | **Nearest-neighbour** | Avoids sub-zero artefacts from bilinear interpolation |
| All others (temp, wind, humidity) | **Bilinear** | Smooth spatial interpolation for continuous fields |

> **Note:** Conservative regridding (area-integrated) would be more physically correct for precipitation but requires `xesmf`. Nearest-neighbour is the documented safe choice for Phase 2.

## Quality Flag Taxonomy

| Flag | Meaning | Action |
|---|---|---|
| `VALID` | Within normal physical range | Use normally |
| `VALID_EXTREME` | Extreme but physically possible (e.g. 350 mm rainfall) | **Keep** — critical for extreme rainfall verification |
| `SUSPICIOUS` | Outside expected range, not definitively wrong | Flag, investigate |
| `MISSING` | NaN or fill value | Track missing fraction |
| `INVALID` | Physically impossible (negative rainfall, temp < −80°C) | Flag, do not delete |

## Adding Real Data

### GFS Data
```bash
# Download GFS GRIB2 from NOMADS
# Place in: data/raw/nwp/gfs/gfs_YYYYMMDD_HHz_f{lead:03d}.grib2
# Example: data/raw/nwp/gfs/gfs_20250715_00z_f024.grib2

# Check status
python scripts/ramp_data.py status
python scripts/ramp_data.py validate gfs
```

### IMD Data
```bash
# Place IMD NetCDF files in: data/raw/observations/imd/
# Annual: imd_rainfall_2024.nc
# Daily:  imd_rainfall_20240715.nc

python scripts/ramp_data.py validate imd
```

### NCMRWF Data
```bash
# NCMRWF NCUM/NEPS requires institutional access from NCMRWF Noida.
# Place NetCDF files in: data/raw/nwp/ncmrwf/ncum/ or neps/
# File format: ncum_YYYYMMDD_HHz_f{lead:03d}.nc

# Configure path in configs/dev.env:
NCUM_DATA_PATH=/path/to/ncum/files
```
